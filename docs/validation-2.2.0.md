# Проверка 2.2.0 перед публикацией

Дата: 6 ноября 2026 года. Среда проверки: Linux, Python 3.12.14, PySide6 6.12.0, fb2cng 1.9.5.

## Выполнено

- До изменений: 17 существующих тестов прошли, один был пропущен из-за отсутствующего fb2cng. После установки официального Linux fb2cng отдельный исходный тест параллельной конвертации прошёл.
- После реализации: `QT_QPA_PLATFORM=offscreen python -m pytest -q tests --ignore=tests/test_network.py` — 59 тестов прошли, пропусков нет (включая дополнение с обложками).
- После заключительной правки поиска отдельно повторён `tests/test_reading_ui.py` — 4 теста прошли; затем добавлена и проверена интеграция обложек в обзор, списки и рекомендации.
- Проверена реальная конвертация FB2 и FB2.ZIP, параллельная обработка нескольких книг, ожидаемая ошибка битой книги, создание KFX, выходной путь и запись в журнал конвертаций.
- Контрольные суммы `core.py`, `library.py`, `ui/convert_tab.py`, `ui/settings_dialog.py`, `updater.py` совпали с сохранёнными до изменений. Их код не изменён. Изменения библиотеки ограничены отображением и редактированием отметок, поиском из трекера и уведомлением новой вкладки об окончании сканирования.
- Новые тесты проверяют точность дат, отсутствие выдуманных дат, отчёты, сохранение истории при переносе файла и сбросе кэша, резервную копию, атомарную массовую запись, влияние оценок без запрета жанров, исключения и разнообразие рекомендаций.
- Проверены возобновление каталога, сохранение старого состава до завершения обновления, смена счётчика при загрузке, повторяющиеся страницы, идентификаторы /book/ и /work/, авторство редакции, отсечение боковых ссылок статьи, CAPTCHA с HTTP 200 и пауза при сетевой ошибке.
- Проверены настоящие окна Qt: отметка в библиотеке и её отражение в трекере, исключение прочитанного из подбора, переход к книге и поиск автора, отмена, читаемость кнопок при тёмной системной палитре. Повреждённая база истории не блокирует конвертер; повреждённый каталог не блокирует историю.
- Два публичных запроса к LiveLib с интервалом 20 секунд выполнились успешно: обнаружены 10 редакционных материалов, прочитана первая страница подборки, сохранён курсор второй страницы. Массовая загрузка всего архива повторно не выполнялась.
- PyInstaller собрал финальное приложение 2.2.0 в Linux; упакованный исполняемый файл запустился, показал новую вкладку, прочитал тестовую SQLite-базу и сохранил снимок окна. Иконка и Windows version-info игнорируются PyInstaller на Linux ожидаемым образом.
- `git diff --check` прошёл. Выпуск, теги, push и изменения облачной конфигурации не выполнялись.

## Дополнение: обложки

- В обзоре, списках и рекомендациях отображаются обложки; для локальных книг — из FB2, для редакционных — из данных LiveLib, при отсутствии изображения — заглушка.
- Из ранее сохранённой статьи извлечены адреса обложек для 76 из 76 книг, из страницы подборки — для 20 из 20. Изображения привязаны к числовым идентификаторам, дополнительные страницы книг не запрашиваются.
- Проверены приоритет локального изображения, сохранение и повторное чтение кэша, ограничения URL, отсечение не-изображений, пауза при HTTP 429, совместимость прежних JSON-записей без поля обложки.
- В реальном интерфейсе проверены несколько загруженных с CDN обложек. Linux-пакет пересобран и повторно запущен; декодирование локальной обложки также проверено в упакованном приложении.

## До выпуска на Windows

Текущая среда не содержит Windows runner. Linux-пакет не является Windows exe. Поэтому следующие пункты остаются обязательными для отдельной Windows-проверки:

1. Собрать Windows-пакет по существующему workflow. Его ручной `workflow_dispatch` загружает артефакт без публикации выпуска; автоматический выпуск в этом workflow выполняется при push в main с новой версией.
2. Проверить запуск, ввод русских названий, сохранение истории и конвертацию на тестовой копии библиотеки в собранном exe.
3. Проверить обновление из 2.1.0 в 2.2.0 и ручной запуск 2.1.0 из отдельной папки. Базы трекера должны остаться, прежняя библиотека и конвертация — работать.
4. Проверить восстановление копии истории и отображение цветов при светлой/тёмной теме Windows.
5. Публиковать выпуск только после отдельного согласования пользователя.

Существующий механизм обновления не изменялся. Приложение не получит 2.2.0 через проверку обновлений, пока выпуск не опубликован.
